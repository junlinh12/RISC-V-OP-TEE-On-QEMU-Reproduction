## 1. 目的

再現を始める前に、ビルドに必要なツールと計算資源がホストにそろっているかを確認し、プロジェクトのディレクトリの骨格を作る。

### 1.1 「条件付き」の理由

ホスト自体はすべての要件を満たしていた。ただし、この Gate の証拠は、後続の Gate より弱い。

- ログを作ったのは、スクリプトの最初の版である。この版はまだ、コマンドごとの終了コードを記録せず、原本（マスク前）のログも保全せず、`pipefail` も使っていなかった。これらは外部レビューを受けて、G01 から導入した。
- 実行時に、スクリプトのハッシュを記録していなかった。このリポジトリの `scripts/gate00_env_check.sh` は、プロジェクトのルートの検出だけを加えた後の版であり、ログを作った版そのものだとは**主張しない**。
- 後続の Gate（G01〜G05）が同じホストで問題なく動いたため、この確認はやり直していない。

## 2. 手順

### Step 1. スクリプトを配置する

このリポジトリを clone した場合は、`scripts/gate00_env_check.sh` がすでにあるので、この手順は不要。スクリプトを個別に入手した場合は、次のようにする。

```bash
mkdir -p ~/projects/RISC-V-OP-TEE-On-QEMU-Reproduction/scripts
cp <download-dir>/gate00_env_check.sh ~/projects/RISC-V-OP-TEE-On-QEMU-Reproduction/scripts/
```

### Step 2. 環境の確認を実行する

```bash
cd ~/projects/RISC-V-OP-TEE-On-QEMU-Reproduction
bash scripts/gate00_env_check.sh
```

スクリプトの動作：

- 読み取り専用で、何もインストールせず、システムの設定も変えない。
- 出力は、マスク処理を通してから `logs/gate00/` に書き込む。マスクするのは、ホームディレクトリのパス、ユーザー名、ホスト名、IPv4 と MAC のアドレス、メールアドレスである。考えられるすべての識別情報を網羅しているわけではないため、公開するログはすべて、公開の前に改めて検査した（G06-1）。
- 初回の実行時に、`logs/`、`scripts/`、`work/` を作る。

### Step 3. ログを確認する

```bash
cat logs/gate00/*.log
```

## 4. 所見

1. 追加でインストールすべきパッケージは無い。
2. 上流のビルド手順は、CMake が 3.30 より新しい場合に限り `CMAKE_POLICY_VERSION_MINIMUM=3.5` を求めている。このホストの CMake は 3.28.3 なので、この回避策は不要と見込んだ。
3. システムの QEMU 8.2.2 は使わない見込みである。Buildroot が RISE の QEMU のフォーク（WorldGuard 対応）をビルドするはずで、起動スクリプトがどの QEMU を起動するかは G01 で確認する。
4. メモリの合計は十分だが、確認時点で 20 GiB が使用中で、スワップも 5.7 GiB 使われていた。G02 のビルドの前に、残っているプロセス（たとえば、ほかのプロジェクトの QEMU）を確認する。
5. `git user.email` が noreply のアドレスではない。公開（G06）の前に、このリポジトリに限って noreply のアドレスを設定する。global の設定は変えない。
6. `ulimit -n 1024` と `umask 0002` は、Buildroot で問題になるとは考えていない。関連するエラーが出たときに限り、見直す。

## 5. G00 で決めたプロジェクトの約束事

- プロジェクトの場所：`~/projects/RISC-V-OP-TEE-On-QEMU-Reproduction`
- ディレクトリの構成：
  - `logs/`：プロジェクトで唯一のログの置き場所（1つのプロジェクトに1つのログの仕組み）
  - `scripts/`：再現用のスクリプト
  - `work/`：ソースとビルドの成果物（公開しない）
  - `docs/`：最後の Gate で作る
- Gate の番号は2桁にする（G00、G01、…）。
- 各 Gate の作業記録は、内容に基づいて `G<NN>_<内容>.md` と名付ける。
- ホスト固有のパスやツールの有無を推測で決めない。G00 のログで確認した値か、ユーザーから提供された値だけを使う。

## 7. まとめ

ホスト（Ubuntu 24.04.5、CPU 20 スレッド、メモリ 30 GiB、ディスクの空き 461 GiB）には、必要なツールとパッケージがすべてそろっており、インストールは不要だった。CMake の回避策も不要だった（G02 のビルドで確認）。結果が「条件付き PASS」なのは、この最初のログが、G01 以降で使ったログの安全策の導入より前のものだからである（1.1 節）。未解決事項は、後続の Gate で解決した（6章）。
