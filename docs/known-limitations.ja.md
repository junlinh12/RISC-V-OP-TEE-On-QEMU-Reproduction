# 既知の限界、逸脱、訂正

English: [known-limitations.md](known-limitations.md)

## 範囲

- **QEMU のみ**：実機では何も実行していない。
- **ソースのレベルの再現**：commit は固定しているが、バイナリのビット単位の一致は想定していない（時刻、パス、ホストのツールの違い）。G01 の4章を参照。
- **2026-11-05/06 に固定**：それ以降の上流の変更は反映していない。RISE のドキュメントとプロジェクトの状況は、2026年11月に読んだもの。

## 公式手順からの逸脱

| 箇所 | 逸脱 | 理由 |
|---|---|---|
| すべての起動 | 起動スクリプトのローカルのコピーで、`hostfwd` を `127.0.0.1` に限定 | ホストの安全のため。上流のスクリプトは変更していない |
| すべての起動 | コンソールの操作を手入力ではなく自動化 | 終了コードを記録するため。ゲストで実行するコマンドは同じ |
| G03 以降 | `-snapshot` を G05a から使用（G03 では未使用） | ディスクイメージを変えないため。G03 では `sdcard.img` が変化した |
| G05b〜G05c のビルド | 全 CPU ではなく 2 並列（`-j2`、`BR2_JLEVEL=2`） | メモリ不足を避けるため。影響するのはビルド時間だけ |
| M8 | optee_test を差し替え：RISE のブランチの代わりに、本家のリリース `4.6.0` | 公式のリポジトリが公開されていないため。PR #852 はコンパイルできなかった（G05c の4章） |
| M8 | QEMU の CPU にベクトル拡張を追加 | M8 の公式手順どおり。ローカルのコピーに適用 |
| M8 の実験 | ドメインの DTB のコピーで、権限の値を1つ変更 | 確定実験。隔離を意図的に弱めたもので、推奨する設定**ではない**（G05c の 5.4 節） |

## 注意が必要な結果

- **G00 は条件付き PASS**：最初のログは、終了コードの記録と原本ログの保全を導入する前のもので、それを作ったスクリプトのハッシュも記録されていない。
- **試験の範囲を伴わない xtest の「OK」**：`regression_1036` と `1038` は Arm 専用（該当しない）。`1037`（アテステーション）と `1041`（fTPM）は PTA や TA が無い（未試験）。M1 では確認済みで、v9 でも同様と思われる（再確認はしていない）。
- **M1 の regression_1039**：1039.1 は実証済み。1039.2 は強く裏付けられている（ツールの不具合のため、完全な検証はできない）。
- **G03 で `sdcard.img` が変化した**：`-snapshot` なしで実行したため。変化したイメージは保全した。
- **M1 の4回の起動のうち1回で停止した**：hart 1 が最初に起動したとき（G05a の 4.1 節）。調査していない。
- **U-Boot でのアクセス違反の後のリセット**：2回目の起動で OP-TEE が panic する（`Page is already mapped`。G05a の 4.2 節）。範囲外。
- **U-Boot は OP-TEE を使えない**（`api uid mismatch`）：ドライバに SMC 方式の経路しかないため（G04 の E1。裏付けあり、実行時には追跡していない）。
- **G04 のアーキテクチャの呼び出しの順序**（Linux → MPXY → ドメインの切り替え → OP-TEE → 戻る）は、ソースの該当箇所で裏付けているが、実行時には追跡していない。
- **M2 / M3 のデモに OP-TEE は加わっていない**：示しているのは OpenSBI の割り込みの仕組みだけ。これを OP-TEE につなぐのは RP022 M1 で、レビュー用に提出済みだが、ここでは再現していない。
- **M8 の regression_1049 は実行していない**（optee_test 4.6.0 に含まれないため）。M8 のドキュメントによれば、このテストはそもそも PMP を観測しない。
- **M8 の TA の失敗**：この再現での原因は確定した。RISE の環境でも同じように失敗するとは主張しない。

## 実証していないこと

- DMA の隔離：これらの構成には IOPMP が無く、PMP が対象とするのはハートからのアクセスだけ。
- OP-TEE が処理するセキュア割り込み。
- リモートアテステーションと fTPM。
- RP016 の M4〜M6 と、M8 以外の RP022 のマイルストーン。
- untrusted ドメインから OP-TEE の領域への書き込みと命令の取り出しの拒否：G05a で試したのは読み出しだけ。

## プロジェクトの途中で行った訂正

| 箇所 | 誤り | 訂正 |
|---|---|---|
| G01 | U-Boot SPL が `u-boot.itb` を読み込むと書いた。ビルドが同一になると主張した | イメージを置くのは QEMU のローダー。再現はソースのレベル |
| G03（撤回した最初の版） | 結果を過大に書いた。すべてのサブキーが ROOT の鍵で署名されていると書いた | 証拠の強さを書き分けて作り直した。連鎖を訂正した |
| G05a v1 | `start-qemu.sh` に `-snapshot` を `--` なしで渡した（QEMU が起動しなかった） | v2 で修正 |
| G05a の自動判定 | U-Boot での読み出しが欠けたため `INCONCLUSIVE` になった | ログを検討した判定：実証済み（Linux 経由の `cause 5`） |
| G05b の作業記録（最初の版） | RP022 M1 を「計画中」と書いた | 状態は「Delivered」（2026-10-29 にパッチを投稿） |
| G05c `gate05c_m8_exp.sh` v1 | ユーザーモードの命令フェッチ例外をすべて数えたため、`REFUTED` になった | v2 は `cause 1` だけを数える。ログを検討した判定は CONFIRMED |

## マスク処理の副作用

- `<EMAIL>` は、無害な文字列（たとえば `user@<UID>.service` の形の systemd のユニット名、パッケージの作者）も置き換えている。
- タイムゾーンは `<TZ>` に置き換えている。
- 大きなログは gzip で圧縮して公開し、URL のクエリ文字列と ANSI のコードを除去している。
